# ADR-021: Bundled PostgreSQL process encoding on Windows

Status: Accepted for isolated implementation; packaged and English Windows CI gates required.

The first remote Windows run converted cmd short-path output to ASCII question marks. UTF-16 output and realpath validation fixed that case, but English Windows still failed `initdb` against a Chinese data directory because native ANSI command-line/file calls lost characters. Local Chinese Windows alone did not expose that failure. Direct data junction initialization and a SUBST-drive experiment also failed; neither is implemented.

During the existing Desktop resource preparation, copy the pinned upstream PostgreSQL package as before, then add the process `activeCodePage=UTF-8` setting to the copied `postgres.exe`, `pg_ctl.exe` and `initdb.exe` manifests. Preserve existing manifest declarations and other PE resources. Use the already resolved, explicitly declared build-only `pe-library@0.4.1`; do not strip or ignore Authenticode certificate data. A signed upstream binary fails preparation and requires a separately reviewed vendor solution. Resource integrity hashes are calculated after preparation.

This follows [Microsoft's documented per-process UTF-8 manifest setting](https://learn.microsoft.com/en-us/windows/apps/design/globalizing/use-utf8-code-page), supported from Windows 10 version 1903. No system locale, registry or drive mapping is changed. The upstream dependency and real data directory remain untouched; there is no migration, copy or move of existing databases. Older Windows versions are not covered by this acceptance.

The local non-BMP directory experiment also reached the native disk-sync phase but exceeded the 60-second startup allowance. Preserve fsync and bound first initialization separately at 120 seconds; ordinary server start remains 60 seconds and stop remains 15 seconds. Existing explicit `startupTimeoutMs` still supplies the initialization limit unless the new optional `initializationTimeoutMs` is provided. Align default embedded RuntimeClient readiness to 180 seconds for initialization plus service bootstrap; external readiness remains 60 seconds and explicit per-call deadlines remain authoritative. This increases a bounded first-start allowance, not retry count or lease ownership.

Production and tests use the same preparation function. Gates cover preservation/idempotency/signed-binary refusal, upstream hash immutability, Chinese and non-BMP resource/data paths, actual initialization and Chinese SQL, stop/restart durability, and the existing installer/portable/clean-render acceptance. Revert the preparation/helper and development dependency to roll back code; business schema and data need no rollback.
